# Test Cases for T2.1.2 - Contact Information Restaurant

Okay, here are two detailed test cases based on the provided task. I've tried to cover different aspects of adding contact information, focusing on both functionality and data integrity.

**Test Case 1**

*   **Title:** Add Valid Venue Manager Contact Details Successfully
*   **Description:** This test case verifies that a user can successfully add valid contact information for a Venue Manager (including phone number and email) and that the information is saved correctly.
*   **Steps:**

    1.  Navigate to the Venue Management section of the application.
    2.  Select a specific venue from the list.
    3.  Navigate to the "Venue Manager" or "Contact Information" tab/section for that venue (the exact wording will depend on the application).
    4.  Locate the "Add Contact" or "Edit Contact" form.
    5.  In the "First Name" field, enter a valid first name (e.g., "John").
    6.  In the "Last Name" field, enter a valid last name (e.g., "Doe").
    7.  In the "Email" field, enter a valid email address (e.g., "john.doe@example.com").
    8.  In the "Phone Number" field, enter a valid phone number (e.g., "123-456-7890").  Make sure the format is supported by the system.
    9.  (If applicable) Select a "Title" or "Position" for the Venue Manager (e.g., "General Manager").
    10. Click the "Save" or "Submit" button.
    11. Verify the application displays a success message.
*   **Expected Result:**

    1.  A success message (e.g., "Contact details saved successfully") is displayed to the user.
    2.  The newly entered contact information (First Name, Last Name, Email, Phone Number, and Title/Position) is displayed correctly in the Venue Manager section.
    3.  The new contact information is persisted in the database and remains associated with the selected venue after refreshing the page or logging out and logging back in.
*   **Priority:** High

**Test Case 2**

*   **Title:** Attempt to Add Venue Manager Contact Details with Invalid Email Format
*   **Description:** This test case verifies the system's ability to handle and reject invalid email address formats when adding Venue Manager contact details.
*   **Steps:**

    1.  Navigate to the Venue Management section of the application.
    2.  Select a specific venue from the list.
    3.  Navigate to the "Venue Manager" or "Contact Information" tab/section for that venue.
    4.  Locate the "Add Contact" or "Edit Contact" form.
    5.  In the "First Name" field, enter a valid first name (e.g., "Jane").
    6.  In the "Last Name" field, enter a valid last name (e.g., "Smith").
    7.  In the "Email" field, enter an *invalid* email address (e.g., "jane.smithexample.com" or "jane.smith@example").
    8.  In the "Phone Number" field, enter a valid phone number (e.g., "987-654-3210").
    9.  (If applicable) Select a "Title" or "Position" for the Venue Manager (e.g., "Assistant Manager").
    10. Click the "Save" or "Submit" button.
*   **Expected Result:**

    1.  An appropriate error message is displayed to the user, indicating that the email address is invalid.  The error message should be clear and informative (e.g., "Please enter a valid email address").
    2.  The contact information is *not* saved.
    3.  The system should prevent the user from proceeding with the save operation until a valid email address is provided.
    4.  The other fields (First Name, Last Name, Phone Number, Title/Position) should remain populated with the entered values, so the user doesn't have to re-enter them after correcting the email address.
*   **Priority:** High
