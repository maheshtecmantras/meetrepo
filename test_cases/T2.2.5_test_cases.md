# Test Cases for T2.2.5 - Venue Profile Clubbing

Okay, I understand the task. Here are two detailed test cases for the "Venue Profile Clubbing" feature, focusing on different aspects of the functionality.

**Test Case 1: Basic Venue Profile Creation and Data Validation**

*   **Title:** Verify Successful Creation and Correct Data Storage of a New Club Venue Profile.
*   **Description:** This test case verifies that a new club venue profile can be successfully created with all required fields and that the entered data is correctly stored and displayed in the system.  It checks the basic creation flow and the integrity of stored data.
*   **Steps:**

    1.  Navigate to the Venue Management section in the application.
    2.  Click the "Add New Venue" or equivalent button.
    3.  Select "Club" as the Venue Type.
    4.  In the "Name of Club" field, enter a valid club name (e.g., "ElectroPulse").
    5.  Upload a valid image file as the "Logo". (Ensure the file meets specified requirements like file type, size, etc.)
    6.  Select "Nightclub" as the "Type" (if available).
    7.  Enter a valid "Commission" percentage (e.g., 15).
    8.  Select "Yes" or "No" for enabling the "Guestlist" feature.  If "Yes", proceed to the following steps.
    9.  Enter a valid time (HH:MM AM/PM) for "Guestlist Open Time" (e.g., 9:00 PM).
    10. Enter a valid time (HH:MM AM/PM) for "Guestlist Closing Time" (e.g., 12:00 AM).
    11. Select "Yes" or "No" for "Indoors".
    12. Select "Yes" or "No" for "Outdoors".
    13. Select "Yes" or "No" for "Bar".
    14. Select "Yes" or "No" for "Special Events".
    15. Enter a valid time (HH:MM AM/PM) for "Venue Opening Time" (e.g., 10:00 PM).
    16. Enter a valid time (HH:MM AM/PM) for "Venue Closing Time" (e.g., 4:00 AM).
    17. Enter a valid integer value for "Max Party Size" (e.g., 200).
    18. Enter "Discount Details" (e.g., "$5 off for early birds").
    19. Enter a "Description/Caption" for the venue (e.g., "The hottest club in town!").
    20. Click the "Save" or "Create Venue" button.
    21. Navigate to the Venue Management section and locate the newly created venue ("ElectroPulse").
    22. Open the venue profile.
*   **Expected Result:**

    1.  The venue profile should be created successfully without any error messages.
    2.  The newly created venue should be visible in the Venue Management list.
    3.  Upon opening the venue profile, all entered data (Club Name, Logo, Type, Commission, Guestlist Status, Guestlist Open Time, Guestlist Closing Time, Indoors Status, Outdoors Status, Bar Status, Special Events Status, Venue Opening Time, Venue Closing Time, Max Party Size, Discount Details, and Description/Caption) should be displayed correctly and match the entered values exactly.
    4.  The logo should display correctly without any broken image issues.
*   **Priority:** High

**Test Case 2: Boundary and Error Condition Testing for Time Fields and Party Size**

*   **Title:** Validate Time and Party Size Field Restrictions in Venue Profile Creation.
*   **Description:** This test case focuses on validating the input restrictions for the Time fields (Guestlist Open/Close, Venue Open/Close) and the Max Party Size field.  It checks for boundary conditions (minimum and maximum values) and error handling when invalid data is entered.
*   **Steps:**

    1.  Navigate to the Venue Management section and initiate the "Add New Venue" flow (as described in Test Case 1).
    2.  Enter valid data for all fields *except* the fields being tested in this case. Use a consistent club name for easier identification (e.g., "TimeWarpClub").
    3.  **Test 1: Guestlist Open Time Before Allowed Minimum:**
        *   Enter a "Guestlist Open Time" that is before the allowed minimum (e.g., a time in the past, or an obviously invalid time like 00:00 AM if the system is configured to not allow past dates).
        *   Click the "Save" button.
    4.  **Test 2: Guestlist Closing Time After Allowed Maximum:**
        *   Enter a "Guestlist Open Time" (e.g., 9:00 PM).
        *   Enter a "Guestlist Closing Time" that is after the allowed maximum (e.g., a time that is later than the venue closing time + x hours).
        *   Click the "Save" button.
    5.  **Test 3: Venue Open Time Invalid Format:**
        *   Enter a "Venue Open Time" in an invalid format (e.g., "25:00 PM", "Invalid Time",  "13:00 AM").
        *   Click the "Save" button.
    6.  **Test 4: Venue Closing Time Before Venue Open Time:**
        *   Enter a "Venue Opening Time" (e.g., 10:00 PM).
        *   Enter a "Venue Closing Time" that is before the "Venue Opening Time" (e.g., 9:00 PM).
        *   Click the "Save" button.
    7.  **Test 5: Max Party Size Below Minimum Allowed:**
        *   Enter a "Max Party Size" below the minimum allowed value (e.g., if the minimum is 10, enter 9).
        *   Click the "Save" button.
    8.  **Test 6: Max Party Size Above Maximum Allowed:**
        *   Enter a "Max Party Size" above the maximum allowed value (e.g., if the maximum is 500, enter 501).
        *   Click the "Save" button.
    9.  **Test 7: Max Party Size Non-Numeric Value:**
        *   Enter a "Max Party Size" using non-numeric characters (e.g., "PartySize", "OneHundred").
        *   Click the "Save" button.
    10. After each "Save" attempt, observe the system's response. Repeat the process with different invalid and boundary values.
*   **Expected Result:**

    1.  For Test 1-7:  The system should *not* save the venue profile.
    2.  For Test 1-7: A clear and informative error message should be displayed to the user, indicating the specific field that is invalid and the reason for the error (e.g., "Guestlist Open Time must be after the current time", "Venue Closing Time cannot be earlier than Venue Opening Time", "Max Party Size must be a number between 10 and 500").
    3.  The invalid data should *not* be saved to the database.
    4.  The previously entered valid data in other fields should be retained to avoid the user having to re-enter all information.
*   **Priority:** High
