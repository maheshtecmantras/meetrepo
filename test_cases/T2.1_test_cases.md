# Test Cases for T2.1 - Venue Profiles Restaurant

Okay, here are two detailed test cases for creating and updating a Venue Profile for a Restaurant, suitable for a Senior QA Engineer to execute and document:

**Test Case 1: Create a New Restaurant Venue Profile with Valid Data**

*   **Title:** Create Restaurant Venue Profile - Valid Data
*   **Description:** This test case verifies the successful creation of a new restaurant venue profile using valid input data for all required and optional fields. It confirms that the profile is created correctly and the data is persisted as expected.
*   **Steps:**

    1.  **Precondition:** User is logged in with appropriate permissions to create venue profiles.
    2.  Navigate to the Venue Management section.
    3.  Click on the "Add Venue" or "Create New Venue" button.
    4.  Select "Restaurant" as the venue type.
    5.  Enter valid data into the following fields:
        *   Venue Name: [e.g., "The Spicy Spoon"]
        *   Address: [e.g., "123 Main Street"]
        *   City: [e.g., "Anytown"]
        *   State/Province: [e.g., "CA"]
        *   Zip/Postal Code: [e.g., "91234"]
        *   Country: [e.g., "USA"]
        *   Phone Number: [e.g., "555-123-4567"]
        *   Email Address: [e.g., "info@spicyspoon.com"]
        *   Website URL: [e.g., "www.spicyspoon.com"]
        *   Description: [e.g., "A family-owned restaurant serving authentic Szechuan cuisine."]
        *   Cuisine Type(s): [e.g., "Szechuan", "Chinese"]
        *   Opening Hours: [e.g., "Mon-Fri: 11:00 AM - 9:00 PM, Sat: 12:00 PM - 10:00 PM, Sun: Closed"]
        *   Price Range: [e.g., "$$"]
        *   Payment Methods: [e.g., "Cash, Credit Card, Debit Card"]
        *   Upload a valid image for the restaurant's logo/profile picture (JPG, PNG).
        *   Specify any other relevant information (e.g., accessibility options, parking availability).
    6.  Click the "Save" or "Create" button.
    7.  Check for successful creation message.
    8.  Navigate to restaurant profiles, search for the restaurant by name and then check the profile of the newly created restaurant.

*   **Expected Result:**

    1.  A success message (e.g., "Venue Profile created successfully") is displayed to the user.
    2.  The user is redirected to the newly created venue profile or venue management page.
    3.  The new restaurant venue profile is created in the system with the exact data entered in the steps.
    4.  The restaurant venue profile is visible in search results or the venue management list.
    5.  The restaurant venue profile page displays all entered information correctly, including the logo/profile picture.
    6.  The restaurant can be associated with other relevant entities in the system (e.g., events, promotions).

*   **Priority:** High

**Test Case 2: Update an Existing Restaurant Venue Profile with Invalid Data**

*   **Title:** Update Restaurant Venue Profile - Invalid Data
*   **Description:** This test case verifies that the system handles invalid data during the update of an existing restaurant venue profile.  It focuses on data validation rules and error handling.
*   **Steps:**

    1.  **Precondition:** User is logged in with appropriate permissions to edit venue profiles. A restaurant venue profile already exists in the system.
    2.  Navigate to the Venue Management section.
    3.  Locate the restaurant venue profile to be updated (e.g., search by name, filter by venue type).
    4.  Click the "Edit" or "Update" button for the selected restaurant venue profile.
    5.  Attempt to update the following fields with invalid data:
        *   Venue Name: [e.g., leave blank or enter special characters only "<>"]
        *   Address: [e.g., enter an extremely long string of characters exceeding the field length limit]
        *   Zip/Postal Code: [e.g., enter an invalid format, such as "AAAAA" or a zip code that doesn't exist.]
        *   Phone Number: [e.g., enter an invalid format, such as "123", or exceed the character limit]
        *   Email Address: [e.g., enter an invalid format, such as "test", "test@", or "test@test"]
        *   Website URL: [e.g., enter an invalid format, such as "test", "test.com" (missing protocol)]
        *   Attempt to upload an invalid image file (e.g., a text file, a very large image, an unsupported format).
        *   Attempt to exceed character limits in other text-based fields (e.g., Description).
    6.  Click the "Save" or "Update" button.

*   **Expected Result:**

    1.  The system *does not* save the changes.
    2.  Appropriate and user-friendly error messages are displayed for each field containing invalid data. The error messages should clearly indicate the reason for the validation failure (e.g., "Invalid email address format," "Zip code must be a 5-digit number," "Venue Name cannot be blank," "Image file format not supported.").
    3.  The system highlights the fields with invalid data, drawing the user's attention to the errors.
    4.  The original, valid data remains in the fields that were not updated.
    5.  Attempting to save the invalid data should not cause a system crash or any unexpected behavior.

*   **Priority:** High
