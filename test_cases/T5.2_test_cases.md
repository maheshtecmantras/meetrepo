# Test Cases for T5.2 - User Status Lifecycle

Okay, here are two detailed test cases covering aspects of managing the user status lifecycle, based on the provided task information. These test cases focus on different aspects: initial status and status change functionality.

**Test Case 1: New User Default Status**

*   **Title:** Verify Default User Status Upon Account Creation

*   **Description:** This test case verifies that a newly created user account is assigned the correct default status (e.g., "Inactive," "Pending Verification," etc.) as defined by the system. This ensures that users are not immediately active without proper verification or activation.

*   **Steps:**

    1.  **Precondition:** Ensure a valid user creation process is available (e.g., signup form, admin panel user creation).  Ensure the system is set up with a defined default user status.
    2.  Navigate to the user creation interface (e.g., signup page or admin user creation form).
    3.  Enter the required user details (e.g., username, email, password, etc.).  Use a unique email address that has not been used before.
    4.  Submit the user creation form.
    5.  Navigate to the user management section of the application (likely within an admin panel or database management tool).
    6.  Search for the newly created user account using the provided username or email address.
    7.  Inspect the user's status field in the database/user management system.

*   **Expected Result:** The newly created user account should have the default status as defined in the system configuration (e.g., "Pending Verification", "Inactive").  The user should *not* be in an "Active" or "Enabled" state immediately after creation, unless that is the designated default.

*   **Priority:** High (Critical for user security and application workflow)

**Test Case 2: User Status Update Functionality**

*   **Title:** Verify User Status Can Be Successfully Updated By An Authorized User

*   **Description:** This test case verifies that an authorized user (e.g., administrator) can successfully update a user's status (e.g., from "Pending Verification" to "Active," "Active" to "Suspended," etc.). This ensures the system can manage user access and privileges appropriately.

*   **Steps:**

    1.  **Precondition:**  A user account exists in the system with a status that can be changed (e.g., "Pending Verification," "Inactive," "Active"). Ensure the test user performing the update has the necessary permissions (e.g., administrator role).
    2.  Log in to the application as an authorized user (e.g., administrator).
    3.  Navigate to the user management section of the application.
    4.  Search for the target user whose status needs to be updated.
    5.  Locate the "Edit" or "Update" button/link associated with the target user.
    6.  Click the "Edit" or "Update" button/link.
    7.  Find the user status field (e.g., a dropdown, radio buttons, or a checkbox).
    8.  Select a new status for the user (e.g., change from "Pending Verification" to "Active").
    9.  Save the changes.
    10. Verify that the status has been updated in the UI.
    11. Log out and then attempt to log in with the user account whose status has been updated. If the status was changed to inactive, the login should fail.

*   **Expected Result:**

    *   The user's status in the user management section of the application is successfully updated to the selected status.
    *   A success message or visual confirmation is displayed to the authorized user confirming the status change.
    *   The change is reflected in the database for that user's record.
    *   If the status was changed to inactive, the user should be unable to log in.

*   **Priority:** High (Critical for user management and security)
