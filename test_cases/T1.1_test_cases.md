**Test Case 1: User Registration KPI Verification**

*   **Title:** Validate User Registration KPI Accuracy

*   **Description:**  This test case verifies the accuracy of the "New User Registrations" KPI. It ensures that when a new user registers, the relevant KPI is correctly incremented and reflects the actual number of new users. This test covers both immediate KPI updates and eventual consistency scenarios.

*   **Steps:**

    1.  **Precondition:** Access the KPI dashboard or reporting tool. Note the current value of the "New User Registrations" KPI for the specified time period (e.g., today, this week, this month). Let's call this initial value "Initial_Registration_Count".
    2.  Navigate to the User Registration page (e.g., website, mobile app).
    3.  Create a new user account with valid credentials (email, username, password, etc.). Complete the registration process.
    4.  **Immediate KPI Check:**  Immediately refresh the KPI dashboard or reporting tool.
    5.  **Delayed KPI Check:** Wait for 5 minutes (or the documented KPI update interval) and refresh the KPI dashboard or reporting tool.
    6.  Create 9 more new user accounts with valid credentials (email, username, password, etc.). Complete the registration process.
    7.  **Immediate KPI Check:**  Immediately refresh the KPI dashboard or reporting tool.
    8.  **Delayed KPI Check:** Wait for 5 minutes (or the documented KPI update interval) and refresh the KPI dashboard or reporting tool.

*   **Expected Result:**

    *   **Immediate KPI Check (Steps 4 & 7):**  The "New User Registrations" KPI should be updated to: `Initial_Registration_Count` + 1 (after creating the first user) and `Initial_Registration_Count` + 10 (after creating the 10 users) immediately after registration, if the system supports immediate KPI updates. Otherwise it should remain the same.
    *   **Delayed KPI Check (Steps 5 & 8):**  The "New User Registrations" KPI should be updated to: `Initial_Registration_Count` + 1 (after creating the first user) and `Initial_Registration_Count` + 10 (after creating the 10 users) within the specified time interval.
    *   The new user registration data should be accurately reflected in any underlying data tables used to generate the KPI (this may require direct database queries or access to backend logs, depending on the testing environment).
    *   No error messages or exceptions are logged during the user registration process.

*   **Priority:** High (Critical for understanding user growth and engagement)

**Test Case 2: Event Attendance Metric Reporting**

*   **Title:** Validate Event Attendance Metric Report

*   **Description:** This test case verifies the accuracy of the "Event Attendance" metric reporting, ensuring that the system correctly records and aggregates attendance data for specific events and venues. This includes confirming that the data is filterable by date range, event, and venue.

*   **Steps:**

    1.  **Precondition:** Access the metric reporting tool or dashboard.  Ensure that test events exist in the system with known expected attendance.  For example:
        *   Event A: Expected attendance = 50
        *   Event B: Expected attendance = 100
        *   Venue X hosts both Event A and Event B.
    2.  Create a new event with a start and end time within the desired date range. Set the venue for the event.
    3.  Record attendance for the event: simulate 25 attendees checking in.
    4.  Generate an "Event Attendance" report for the selected date range encompassing the new event.  Filter the report to show the "Total Attendance" for all events within that date range.
    5.  Generate an "Event Attendance" report for the selected date range, filtered to show the "Total Attendance" for only the newly created event.
    6.  Generate an "Event Attendance" report filtered by Venue X within the same date range.
    7.  Generate an "Event Attendance" report filtering by Event A, and Event B individually.

*   **Expected Result:**

    *   **Step 4:** The "Total Attendance" metric in the report should reflect the sum of attendance for all events within the selected date range (should include 50 (Event A) + 100 (Event B) + 25 (new event)= 175)
    *   **Step 5:** The "Total Attendance" metric in the report should show 25.
    *   **Step 6:** The "Total Attendance" metric filtered by Venue X should show 175 (50 (Event A) + 100 (Event B) + 25 (new event)).
    *   **Step 7:** The "Total Attendance" metric filtered by Event A should show 50, and Event B should show 100.
    *   The report should display accurate event names, venue names, dates, and attendance figures.
    *   The report should be generated without errors.
    *   The report should adhere to the expected formatting (e.g., column headers, data types).

*   **Priority:** High (Essential for tracking event performance and venue utilization)
