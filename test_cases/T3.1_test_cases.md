**Test Case 1: Guestlist Sign-Up Metric Tracking**

*   **Title:** Validate Guestlist Sign-Up Count Accuracy

*   **Description:** This test case verifies that the guestlist sign-up metric accurately reflects the number of users who successfully sign up through the designated channels. It ensures no sign-ups are missed or double-counted.

*   **Steps:**

    1.  **Pre-condition:** Ensure the metrics dashboard/reporting tool is accessible and configured to display guestlist sign-up data.
    2.  **Pre-condition:** Have access to user registration pages and backend data.
    3.  Navigate to the guestlist sign-up page (e.g., website form, mobile app screen, landing page).
    4.  Manually sign up *N* new users using distinct email addresses and valid information.  Record the details of each sign-up (email, name, timestamp).  *Note: N should be at least 5 to provide a sufficient sample size.*
    5.  Wait for the system to process the sign-ups (observe any system delay based on documentation or prior testing).
    6.  Access the metrics dashboard/reporting tool.
    7.  Locate the guestlist sign-up metric for the relevant time period (the time period covering the sign-ups in step 4).
    8.  Query the backend database table where user sign-up information is stored (e.g., `users`, `guestlist_signups`).
    9.  Write a SQL query to count all rows created with a timestamp within the defined time period.

*   **Expected Result:**

    *   The guestlist sign-up metric displayed on the dashboard/reporting tool should accurately reflect the number of new users signed up (*N* from step 4).
    *   The number of rows returned from the database query performed in step 8 should also equal *N*.
    *   There should be an exact match in the email addresses and timestamps between the manually recorded sign-ups and the details displayed in the dashboard and stored in the database.
    *   There should be no duplicate sign-ups recorded for the same user (identified by email address).

*   **Priority:** High

**Test Case 2: Discount Usage Metric Tracking & Revenue Calculation**

*   **Title:** Validate Discount Usage and Revenue Generation Accuracy

*   **Description:** This test case verifies that the system accurately tracks the usage of discounts and correctly calculates the revenue generated after applying those discounts.

*   **Steps:**

    1.  **Pre-condition:** Ensure the metrics dashboard/reporting tool is accessible and configured to display discount usage and revenue data.
    2.  **Pre-condition:** Configure *M* unique discount codes (e.g., 10%, $5 off, free item). Record the code, discount percentage/amount, and applicable product/service.
    3.  Create *K* test transactions using each of the *M* discount codes at least once.  Vary the products/services being purchased in each transaction. Record the details of each transaction: Discount code used, products purchased, original price, discounted price, final price, and timestamp.
    4.  Do *X* test transactions using no discount codes. Record the details of each transaction: Products purchased, original price, final price, and timestamp.
    5.  Wait for the system to process the transactions and update the metrics (observe any system delay).
    6.  Access the metrics dashboard/reporting tool.
    7.  Locate the discount usage metric and the revenue generated metric for the relevant time period (the time period covering the transactions in steps 3 and 4).
    8.  Manually calculate the expected revenue based on the recorded transaction details (original price - discount amount = discounted price). Calculate the expected usage of each discount code.
    9.  Query the backend database table where transaction information is stored (e.g., `orders`, `transactions`).
    10. Write SQL queries to:
        *   Count the usage of each discount code within the specified time period.
        *   Calculate the sum of the 'final_price' column for all transactions within the specified time period.

*   **Expected Result:**

    *   The discount usage metric displayed on the dashboard/reporting tool should accurately reflect the number of times each discount code was used (*K* transactions, with each of the *M* codes used at least once). The database count for each discount code usage must match the expected count.
    *   The revenue generated metric displayed on the dashboard should match the manually calculated revenue (sum of all final prices across all transactions in steps 3 and 4).
    *   The revenue generated metric should also match the sum of 'final_price' from the database query.
    *   Verify that discounts are applied correctly to the original price as intended for all transactions. No over discounting or under discounting observed.

*   **Priority:** High

**Important Considerations:**

*   **Data Accuracy:** The most critical aspect is to ensure that the metrics are accurate. This involves rigorous validation against source data (e.g., database records, user input).
*   **Time Period:** Pay attention to the time periods being reported on. Verify that the metrics are correctly aggregating data within the specified timeframes.
*   **Edge Cases:** Consider edge cases, such as:
    *   Invalid discount codes.
    *   Expired discounts.
    *   Users signing up with invalid email addresses.
    *   Transactions that are refunded or cancelled.
    *   Multiple discount usage for one transaction (if allowed by the system).
*   **Performance:** Monitor the performance of the metrics dashboard/reporting tool, especially when dealing with large datasets.
*   **Data Refresh Rate:** Understand how frequently the metrics are updated and verify that the refresh rate meets the business requirements.
*   **Reporting Tool Functionality:** Check any reporting features that allow for further filtering, drill down of detail, custom reports, CSV exports, etc.

These test cases provide a starting point and can be further refined based on the specifics of your application and requirements. Remember to document all test results and any issues encountered. Good luck!
