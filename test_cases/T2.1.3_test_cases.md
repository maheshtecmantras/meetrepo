# Test Cases for T2.1.3 - Business Agreement Details Restaurant

Okay, I will create two detailed test cases for the given task "Business Agreement Details Restaurant: Add Commission structure, discount rates". These test cases will focus on different aspects of adding the commission structure and discount rates.

Here are the two test cases:

**Test Case 1: Adding a Fixed Percentage Commission Structure**

*   **Title:** Verify Successful Addition of Fixed Percentage Commission Structure for Restaurant

*   **Description:** This test case verifies that a user can successfully add a new commission structure for a restaurant, using a fixed percentage commission type, and that the data is saved correctly and displayed as expected.

*   **Steps:**

    1.  Navigate to the "Business Agreement Details" page for a specific restaurant.
    2.  Locate the "Commission Structure" section.
    3.  Click the "Add Commission Structure" button.
    4.  Select "Fixed Percentage" as the commission type from the dropdown menu.
    5.  Enter a valid percentage value (e.g., "15") into the "Commission Percentage" field.
    6.  Select a start date for the commission structure from the date picker (e.g., "2024-01-01").
    7.  Optionally, enter an end date for the commission structure from the date picker (e.g., "2024-12-31").  If no end date is entered, the commission structure should be considered ongoing.
    8.  Click the "Save" or "Add" button.
    9.  A success message should be displayed (e.g., "Commission structure added successfully.").
    10. Refresh the page.

*   **Expected Result:**

    1.  The new commission structure with the specified percentage and start/end dates is displayed in the "Commission Structure" table or list for the restaurant.
    2.  The commission type is correctly displayed as "Fixed Percentage".
    3.  The Commission Percentage should be correctly displayed as "15%".
    4.  The Start Date is correctly displayed as "2024-01-01".
    5.  The End Date, if provided, is correctly displayed as "2024-12-31". If no end date was provided, then the End Date column should display as "Ongoing" or have a specific message stating that the commission is ongoing.
    6. The information in the database for this restaurant is correctly updated with the commission details.
    7.  No error messages are displayed.

*   **Priority:** High

**Test Case 2: Adding and Validating a Discount Rate with Date Range**

*   **Title:** Verify Successful Addition and Validation of Discount Rate with Start and End Dates

*   **Description:** This test case verifies the ability to add a discount rate with a specific start and end date range to the restaurant's business agreement details, and validates that the date range is correctly enforced (e.g., prevent overlapping date ranges with existing discounts).

*   **Steps:**

    1.  Navigate to the "Business Agreement Details" page for a specific restaurant.
    2.  Locate the "Discount Rates" section.
    3.  Click the "Add Discount Rate" button.
    4.  Enter a valid discount percentage value (e.g., "10") into the "Discount Percentage" field.
    5.  Select a start date for the discount from the date picker (e.g., "2024-07-01").
    6.  Select an end date for the discount from the date picker (e.g., "2024-07-31").
    7.  Enter a valid discount name (e.g., "Summer Promotion").
    8.  Click the "Save" or "Add" button.
    9.  A success message should be displayed (e.g., "Discount rate added successfully.").
    10. Attempt to add another discount rate with a date range that overlaps with the previously added discount (e.g., Start Date: "2024-07-15", End Date: "2024-08-15").
    11. Attempt to add a discount rate with invalid start date (e.g. a start date in the past)

*   **Expected Result:**

    1.  The new discount rate with the specified percentage, start date, and end date is displayed in the "Discount Rates" table or list for the restaurant.
    2.  The Discount Percentage is correctly displayed as "10%".
    3.  The Start Date is correctly displayed as "2024-07-01".
    4.  The End Date is correctly displayed as "2024-07-31".
    5.  The discount name is displayed correctly as "Summer Promotion".
    6.  When attempting to add an overlapping discount rate (Step 10), an error message should be displayed indicating a date conflict (e.g., "The specified date range overlaps with an existing discount."). The new overlapping discount should not be saved.
    7. When attempting to add a discount rate with invalid start date (Step 11), an error message should be displayed indicating that the start date is invalid.
    8. The information in the database for this restaurant is correctly updated with the discount details.
    9.  No other unexpected error messages are displayed.

*   **Priority:** High
