# Test Cases for T5.4.1 - Invite User

Okay, here are two detailed test cases based on the "Invite User" task. One will focus on the email invitation flow, and the other will focus on invite link generation.

**Test Case 1: Invite User via Email - Successful Invitation**

*   **Title:** Invite User via Email - Successful Invitation

*   **Description:** This test case verifies the successful invitation of a new user to the system using a valid email address. It covers sending the invitation, receiving the invitation email, and successfully completing the registration process.

*   **Steps:**

    1.  **Pre-Condition:** An administrator or user with "invite user" permission is logged into the application.
    2.  Navigate to the "Invite User" section of the application (e.g., under "User Management", "Settings", etc.).
    3.  Enter a valid, unused email address in the "Email Address" field (e.g., `testuser123@example.com`). The test email account `testuser123@example.com` should have access.
    4.  Enter a first name in the "First Name" field (e.g., "Test").
    5.  Enter a last name in the "Last Name" field (e.g., "User").
    6.  (Optional, if applicable) Assign a specific role or permission to the invited user (e.g., "Editor", "Viewer").
    7.  (Optional, if applicable) Customize the invitation message (if the feature allows).
    8.  Click the "Send Invitation" button.
    9.  Observe the system for a confirmation message indicating the invitation was successfully sent (e.g., "Invitation sent to testuser123@example.com").
    10. Check the email inbox of `testuser123@example.com`. Verify that an invitation email has been received.
    11. Inspect the email content:
        *   Verify the sender's address is correct.
        *   Verify the email subject is appropriate (e.g., "You're invited to [Application Name]").
        *   Verify the email body contains a personalized message (if applicable) and a clear call to action (e.g., "Click here to register").
    12. Click the invitation link in the email. This should redirect to the registration page of the application.
    13. On the registration page, complete the registration form by creating a password, confirming the password, and accepting any terms of service (if required).
    14. Submit the registration form.
    15. Log in with the new user account (`testuser123@example.com` and the newly created password).

*   **Expected Result:**

    1.  The confirmation message after sending the invitation should be displayed without errors.
    2.  An invitation email is received in the specified email inbox within a reasonable timeframe (e.g., 5 minutes).
    3.  The invitation email contains the correct sender address, subject, personalized message and a valid registration link.
    4.  Clicking the invitation link redirects the user to the registration page.
    5.  The user is able to successfully complete the registration process without errors.
    6.  The user is able to successfully log in to the application with the newly created account.
    7. (Optional) After the registration is complete, the invite status should be updated in the system to "Accepted" or "Registered".

*   **Priority:** High

**Test Case 2: Generate Invite Link - Valid Link and Redemption**

*   **Title:** Generate Invite Link - Valid Link and Redemption

*   **Description:** This test case verifies the functionality of generating a unique invite link. It tests whether the generated link is valid, and the new user is able to complete their registration through that link.

*   **Steps:**

    1.  **Pre-Condition:** An administrator or user with "generate invite link" permission is logged into the application.
    2.  Navigate to the "Invite User" section of the application (e.g., under "User Management", "Settings", etc.).
    3.  Locate and click the "Generate Invite Link" or similar button/option.
    4.  (Optional, if applicable) Set an expiration date or usage limit for the generated link (e.g., expire after 24 hours, limit to 1 usage).
    5.  (Optional, if applicable) Assign a specific role or permission to users who register using this link (e.g., "Contributor", "Trial User").
    6.  Confirm the generation of the invite link.
    7.  Copy the generated invite link from the system's display.
    8.  Open a new browser window or incognito window to ensure a clean browsing session without existing user authentication.
    9.  Paste the copied invite link into the address bar of the new browser window and press Enter.
    10. Verify that the invite link redirects to the registration page of the application.
    11. On the registration page, complete the registration form with valid information (e.g., email address `testuser234@example.com`, first name, last name, password). The test email account `testuser234@example.com` should have access.
    12. Submit the registration form.
    13. Log in with the new user account (`testuser234@example.com` and the newly created password).

*   **Expected Result:**

    1.  The system successfully generates an invite link.
    2.  The invite link is displayed correctly and is easily copyable.
    3.  Pasting the link into a browser redirects to the registration page.
    4.  The user is able to successfully complete the registration process using the invite link.
    5.  The user is able to successfully log in to the application with the newly created account.
    6.  (Optional) If a usage limit was set, the link should become invalid after the specified number of uses.  Attempting to use it again should display an error message.
    7.  (Optional) If an expiration date was set, the link should become invalid after the specified date/time. Attempting to use it after expiration should display an error message.
    8.  (Optional) The newly registered user should be assigned the correct role/permission specified during link generation.

*   **Priority:** High

These test cases cover two common paths within the "Invite User" functionality. Remember to adapt these to the specific features and design of your application.  Further test cases would cover:

*   Invalid email formats
*   Invalid phone number formats (if applicable)
*   Already-registered email addresses
*   Expired invite links
*   Using invite links after the usage limit has been reached
*   Negative tests around permission/role assignment
*   Testing the behavior of the application when the email server is unavailable.
