# Test Cases for T7.2 - Venue Manager

Okay, here are two detailed test cases designed for a Venue Manager role with limited access, focusing on different aspects of the provided description: "Limited access to their own venue’s profile, events, and stats."  I've aimed for good coverage with one focused on Profile and Event access, and the other on Stats limitations.

**Test Case 1: Venue Manager - Profile and Event Access/Modification**

*   **Title:** Venue Manager - Verify Limited Profile and Event Access & Modification Capabilities

*   **Description:** This test case verifies that a Venue Manager user role has the appropriate level of access to view and modify their assigned venue's profile information and event details, and that they cannot access other venues' information or perform actions beyond their authorized scope.

*   **Steps:**

    1.  **Login:** Log in to the application as a Venue Manager using valid credentials.  Ensure the user is associated with a specific Venue (e.g., "Venue A").
    2.  **Navigate to Venue Profile:** Navigate to the section of the application that allows access to Venue Profiles. (e.g., "Manage Venues" or "My Venue").
    3.  **Verify Profile Display:** Verify that the Venue Manager can view the profile details of their assigned Venue A (name, address, contact information, description, images, etc.).
    4.  **Attempt Profile Modification:** Attempt to modify editable fields within Venue A's profile (e.g., venue description, contact phone number, opening hours).
    5.  **Save Profile Changes:** Save the attempted changes to the profile.
    6.  **Verify Successful Save:** Confirm that the profile changes have been successfully saved and are reflected in the venue profile display.
    7.  **Navigate to Other Venue Profile:** Attempt to navigate or directly access the profile of a different Venue (e.g., "Venue B") using the UI or by manipulating the URL.
    8.  **Verify Event Creation Access:** Navigate to the Event Management section.
    9.  **Attempt to Create New Event:** Attempt to create a new event and associate it with Venue A.
    10. **Verify Event Creation Success:** Ensure the event can be created and associated with Venue A.
    11. **Attempt to Create New Event for Other Venue:** Attempt to create a new event and associate it with Venue B.
    12. **Verify Event Modification Access:** Select an existing event associated with Venue A.
    13. **Attempt to Modify Event:** Attempt to modify editable fields within the event associated with Venue A (e.g., event name, date, time, description).
    14. **Save Event Changes:** Save the attempted changes to the event.
    15. **Verify Successful Save:** Confirm that the event changes have been successfully saved and are reflected in the event details.
    16. **Attempt to Modify Event for Other Venue:** Select an existing event associated with Venue B.
    17. **Attempt to Modify Event for Other Venue:** Attempt to modify editable fields within the event associated with Venue B.

*   **Expected Result:**

    1.  The Venue Manager should be able to log in successfully.
    2.  The Venue Manager should be able to access and view the profile of their assigned Venue A.
    3.  The Venue Manager should be able to successfully modify permitted fields in Venue A's profile and save the changes.
    4.  The Venue Manager should be **unable** to access or view the profile of Venue B.  The system should display an error message like "Access Denied" or redirect them to a page indicating insufficient permissions.
    5.  The Venue Manager should be able to create new events and associate them with Venue A.
    6.  The Venue Manager should be **unable** to create new events and associate them with Venue B.  The system should prevent this association or display an appropriate error.
    7.  The Venue Manager should be able to successfully modify permitted fields in Venue A's events and save the changes.
    8.  The Venue Manager should be **unable** to access or modify the profile of Venue B's events.  The system should display an error message like "Access Denied" or redirect them to a page indicating insufficient permissions.

*   **Priority:** High

**Test Case 2: Venue Manager - Verify Limited Stats Access**

*   **Title:** Venue Manager - Verify Limited Access to Venue Statistics

*   **Description:** This test case verifies that the Venue Manager user role has access only to statistics relevant to their assigned venue and that access to global statistics or statistics for other venues is restricted. This includes both viewing and potential report generation.

*   **Steps:**

    1.  **Login:** Log in to the application as a Venue Manager using valid credentials associated with Venue A.
    2.  **Navigate to Stats Section:** Navigate to the section of the application that displays venue statistics (e.g., "Analytics," "Reports," "Venue Performance").
    3.  **Verify Venue A Stats Display:** Verify that the Venue Manager can view statistics related to Venue A.  (e.g., Number of events, Average attendance, Revenue generated, Popular event types, Customer demographics, etc.)  For each stat, confirm the data displayed is reasonable and relevant.
    4.  **Attempt to Access Global Stats:** Attempt to navigate or access any section displaying global or aggregated statistics across all venues (if such a section exists). This might involve exploring different tabs, dropdown menus, or URL manipulation.
    5.  **Attempt to Access Stats for Venue B:** Attempt to navigate or directly access statistics related to Venue B. This might involve selecting a specific venue from a dropdown menu or manipulating the URL.
    6.  **Verify Report Generation (if applicable):** If the application allows for report generation, attempt to generate reports for Venue A statistics.
    7.  **Verify Report Generation (if applicable):** If the application allows for report generation, attempt to generate reports for Global statistics or Venue B statistics.

*   **Expected Result:**

    1.  The Venue Manager should be able to log in successfully.
    2.  The Venue Manager should be able to access and view relevant statistics for Venue A. The displayed metrics should be relevant and accurate.
    3.  The Venue Manager should be **unable** to access global statistics.  The system should either prevent access, display an error message ("Insufficient Permissions"), or redirect them to a permitted page.
    4.  The Venue Manager should be **unable** to access statistics for Venue B. The system should either prevent access, display an error message ("Access Denied"), or redirect them to a permitted page.
    5.  If report generation is available, the Venue Manager should be able to successfully generate reports for Venue A statistics. The report should contain accurate and relevant information.
    6.  If report generation is available, the Venue Manager should be **unable** to generate reports for global statistics or statistics for Venue B.  The system should prevent this action, display an error message, or generate an empty/invalid report.

*   **Priority:** High

These two test cases provide a solid foundation for verifying the "limited access" constraint for the Venue Manager role. Remember to adapt them to the specific features and UI of your application.  Also, consider adding negative test cases (e.g., attempting to inject malicious code into profile fields, trying to bypass access controls using browser developer tools) for more robust security testing.
