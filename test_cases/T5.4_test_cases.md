# Test Cases for T5.4 - Invitation & Activation Flow

Okay, here are two detailed test cases designed to cover the Invitation & Activation flow, keeping in mind a senior QA engineer's perspective.  I've tried to focus on areas that are commonly problematic and added considerations for scalability and security.

**Test Case 1: Successful User Invitation and Account Activation**

*   **Title:**  Successful User Invitation and Account Activation via Email

*   **Description:**  This test case verifies the complete and successful flow of a new user being invited to the system via email, receiving the invitation, and successfully activating their account and logging in.  Focus is on ensuring the email is received, the activation link is valid, the user can set a password, and that login is successful after activation.

*   **Steps:**

    1.  **Preparation:**
        *   Ensure a valid, unused email address is available for the new user.
        *   Ensure that the email server used by the application is properly configured and sending emails.
        *   Clear browser cache and cookies or use a private browsing window to simulate a new user experience.
    2.  **Invitation:**
        *   As an administrator or user with invitation privileges (specify which user role!), navigate to the user management/invitation section of the application.
        *   Enter the valid, unused email address into the invitation form.
        *   Enter any required fields for the user invitation (e.g., first name, last name, role).
        *   Submit the invitation.
        *   Verify that the application indicates the invitation has been successfully sent.
    3.  **Email Verification:**
        *   Access the email inbox of the email address used for the invitation.
        *   Verify that an invitation email is received within a reasonable timeframe (e.g., 5 minutes).  If not received, check spam/junk folders.
        *   Examine the email content: Verify sender name, subject line, and body of the email are accurate and professional. The email should contain a clear call to action (e.g., "Activate Your Account").
    4.  **Activation:**
        *   Click the activation link in the invitation email.
        *   The user should be redirected to the account activation page within the application.
        *   On the activation page, enter a valid password that meets the application's password policy requirements (if any). Note: capture password policy rules before executing this test.
        *   Confirm the password.
        *   Submit the password.
    5.  **Login Verification:**
        *   The user should be automatically redirected to the login page or successfully logged in.
        *   If redirected to the login page, enter the email address used for the invitation and the newly created password.
        *   Submit the login credentials.

*   **Expected Result:**

    1.  The application displays a success message upon submitting the invitation.
    2.  The invitation email is received in the user's inbox within the specified timeframe and is not marked as spam.  The email content is accurate and professional.
    3.  Clicking the activation link redirects the user to a valid account activation page.
    4.  The user is able to successfully set and confirm a password that meets the password policy.
    5.  The user is either automatically logged in to the application after submitting the password, OR successfully logs in using the newly created credentials.
    6.  After successful login, the user is redirected to the expected dashboard or landing page based on their role.
    7.  The newly created user account is visible and active within the user management section of the application.

*   **Priority:** High

**Test Case 2:  Failed Invitation Activation - Expired Token**

*   **Title:**  Failed Invitation Activation - Expired Activation Token

*   **Description:**  This test case verifies that the application correctly handles expired activation tokens (links).  This ensures that users cannot activate their accounts using an outdated or compromised link, thereby improving security.

*   **Steps:**

    1.  **Preparation:**
        *   Invite a user using the invitation flow (as in Test Case 1, Steps 1-2).
        *   **Crucially:**  Before clicking the activation link in the invitation email, wait until the activation token is expected to expire.  Determine the expiry timeframe first by:
            *   Consulting the system documentation (if available).
            *   Inquiring with developers about the token expiry configuration.
            *   As a last resort, making an educated guess (e.g., 24 hours) and setting a timer.
        *   Once the estimated expiry time has passed (plus a small buffer, e.g., 1 hour beyond the expected expiry), proceed to the next step.
    2.  **Attempt Activation with Expired Token:**
        *   Click the activation link in the original invitation email.

*   **Expected Result:**

    1.  The application should display a clear and user-friendly error message indicating that the activation token is expired.  Example message: "This activation link is no longer valid. Please request a new invitation."
    2.  The user should *not* be able to proceed to the password setting page.
    3.  Attempting to manually navigate to the password setting page (e.g., by guessing the URL) should also result in the same error message.
    4.  The user account should *not* be activated.  If an administrator checks the user management section, the user's status should remain as "Pending Activation" or similar.
    5.  Clicking the link multiple times shouldn't cause any unexpected errors or system instability.
    6.  (Optional, but good practice) The error message should provide a clear call to action, such as directing the user to request a new invitation or contact support.

*   **Priority:** High
