# Test Cases for T5.5 - Referral Tracking

Okay, here are two detailed test cases covering aspects of the "Referral Tracking" task, focusing on the Referral Dashboard and Referral Rewards functionality. I've tried to cover different aspects with each test case.

**Test Case 1: Referral Dashboard - Tracking Referrals and Statuses**

*   **Title:** Referral Dashboard - Verify Referral Listing and Status Updates

*   **Description:** This test case verifies that the Referral Dashboard correctly displays a list of referrals, their current statuses (e.g., "Pending," "Accepted," "Declined"), and that the statuses are updated accurately based on actions taken on the referred user. It tests the core functionality of monitoring the referral progress.

*   **Steps:**

    1.  **Pre-Condition:** Ensure that a user account exists and is logged in (User A - Referrer). Ensure Referral Rewards system is enabled in backend.
    2.  **Pre-Condition:** Ensure at least 3 referrals are initiated by User A, each with a different potential outcome:
        *   Referral 1: The referred user (User B) has registered but has not yet completed the required action (e.g., making a purchase, completing profile).
        *   Referral 2: The referred user (User C) has registered and has successfully completed the required action.
        *   Referral 3: The referred user (User D) has declined the invitation or the referral has expired.
    3.  Log in to the application as User A (Referrer).
    4.  Navigate to the "Referral Dashboard" (Location may vary according to application).
    5.  Verify that the dashboard displays a list of all referrals initiated by User A.
    6.  For each referral listed, verify the following information:
        *   Referred User's Identifier (e.g., Name, Email, Username - whatever is displayed).
        *   Date of Referral.
        *   Current Status of the Referral (e.g., "Pending Registration," "Pending Action," "Completed," "Declined," "Expired").
    7.  Compare the status of each referral on the dashboard to the actual status of the referred user (e.g., check if User B is indeed registered but has not completed the purchase).
    8.  Simulate the referred user (User B) completing the required action (e.g., complete the purchase).
    9.  Refresh the Referral Dashboard.
    10. Verify that the status of User B's referral has changed to "Completed" or appropriate equivalent.
    11. Navigate to the referred user list in the backend and mark User D's referral as declined.
    12. Refresh the Referral Dashboard.
    13. Verify that the status of User D's referral has changed to "Declined" or appropriate equivalent.

*   **Expected Result:**

    *   The Referral Dashboard should display a complete and accurate list of all referrals initiated by the logged-in user.
    *   Each referral should display the correct referred user identifier, date of referral, and current status.
    *   The displayed statuses must accurately reflect the actual status of the referred users (registration, action completion, decline, expiry).
    *   The dashboard should update in a reasonable time frame (e.g., within 5 seconds) to reflect status changes triggered by actions taken by referred users.
    *   The status is updated correctly in the dashboard after the user in backend is marked as declined.

*   **Priority:** High (Core functionality of the referral program)

**Test Case 2: Referral Rewards - Verify Reward Issuance and Crediting**

*   **Title:** Referral Rewards - Verify Issuance and Crediting of Rewards to Referrer

*   **Description:** This test case verifies that when a referred user completes the required action, the referrer receives the correct reward (e.g., points, discount, credit) and that the reward is correctly credited to the referrer's account.

*   **Steps:**

    1.  **Pre-Condition:** Ensure a user account exists and is logged in (User A - Referrer). Ensure Referral Rewards system is enabled in backend. Define the reward for a successful referral (e.g., 10 points). Ensure that the reward is configured to be issued after the referred user completes a specific action.
    2.  **Pre-Condition:** The system requires the referred user to complete a purchase of at least $50 in order for the referrer to receive the reward.
    3.  Log in to the application as User A (Referrer). Note User A's current balance/points total before the referral bonus is applied.
    4.  Have User A refer a new user (User B).
    5.  Have User B register for an account using the referral link.
    6.  As User B, complete the required action that triggers the reward for the referrer (e.g., purchase of $50).
    7.  Log back in as User A (Referrer).
    8.  Verify that User A's account balance/points total has been increased by the configured reward amount (e.g., 10 points).
    9.  Check User A's transaction history to confirm the referral reward is listed.
    10. Repeat steps 4-9, but have User B only purchase $20 worth of goods.
    11. Verify that User A's account balance/points total has NOT increased and there is no record of a reward in the transaction history.
    12. Check email inbox of User A (Referrer). Verify that User A received a notification email for successful referral.

*   **Expected Result:**

    *   When a referred user completes the action that triggers the reward, the referrer's account balance/points total should be increased by the correct amount.
    *   A record of the referral reward should be present in the referrer's transaction history.
    *   The system should not issue a reward if the referral did not meet the requirments.
    *   User A (Referrer) should receive a notification email for successful referral.
    *   If the action that triggers the reward isn't complete, the referrer's account balance/points total should not be increased.

*   **Priority:** High (Critical for the incentive aspect of the referral program)

**Important Considerations:**

*   **Environment:** These test cases should be executed in a test environment that mirrors the production environment as closely as possible.
*   **Data:** Use a dedicated set of test data for referral testing to avoid polluting production data.
*   **Negative Testing:**  These are primarily positive test cases.  Expand on these with negative test cases (e.g., referral of an existing user, referral code manipulation, attempts to credit rewards multiple times).
*   **Performance:** Consider performance testing, especially if the referral program is expected to handle a large number of referrals.
*   **Security:**  Test for potential security vulnerabilities such as referral fraud or manipulation.
*   **Edge Cases:**  Consider edge cases such as referring users with very long usernames, email addresses, or other potentially problematic data.
*   **Localization:**  If the application is localized, ensure that the referral program is properly localized as well (date formats, currency symbols, etc.).
*   **Email Notifications:** Test the content and delivery of referral-related email notifications. Verify that the emails are properly formatted and contain accurate information.
*   **Reporting:** Verify that the system generates accurate and comprehensive reports on referral activity. This includes the number of referrals, conversion rates, and the amount of rewards issued.

These test cases provide a solid starting point.  Remember to adapt and expand them based on the specific requirements and complexity of your referral program.  Good luck!
