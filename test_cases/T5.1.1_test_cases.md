# Test Cases for T5.1.1 - Personal Details

Okay, I'm ready to create two detailed test cases for the "Personal Details" task. Here they are:

**Test Case 1:  Valid Name, Email, and Phone Number Submission**

*   **Title:** Verify Successful Submission of Valid Personal Details

*   **Description:** This test case verifies that a user can successfully submit their personal details (Name, Email, and Phone Number) when all input values conform to the system's validation rules and constraints. It ensures the system accepts and processes valid data as expected.

*   **Steps:**

    1.  Navigate to the "Personal Details" form.
    2.  Enter a valid name in the "Name" field (e.g., "John Doe").  (Assume validation allows alphanumeric characters and spaces)
    3.  Enter a valid email address in the "Email" field (e.g., "john.doe@example.com"). (Assume standard email format validation)
    4.  Enter a valid phone number in the "Phone Number" field (e.g., "123-456-7890"). (Assume validation requires a specific format with hyphens)
    5.  Click the "Submit" button.
    6.  Observe the system's response.

*   **Expected Result:**

    1.  The system displays a success message indicating the personal details have been successfully submitted (e.g., "Personal details saved successfully!").
    2.  The page either refreshes to a clean state or navigates to the next logical page (e.g., a confirmation page).
    3.  (If possible) Verify that the submitted data ("John Doe", "john.doe@example.com", "123-456-7890") is correctly stored in the relevant database or data store (back-end verification). This may require access to the database or API endpoint.

*   **Priority:** High

**Test Case 2:  Invalid Email Format Submission**

*   **Title:** Verify Error Message Displayed for Invalid Email Format

*   **Description:** This test case verifies that the system correctly validates the email address input field and displays an appropriate error message when the entered email address does not conform to the expected format. This ensures that users are guided to enter valid email addresses.

*   **Steps:**

    1.  Navigate to the "Personal Details" form.
    2.  Enter a valid name in the "Name" field (e.g., "John Doe"). (Assume validation allows alphanumeric characters and spaces)
    3.  Enter an *invalid* email address in the "Email" field (e.g., "john.doeexamplecom" - missing the '@' symbol).
    4.  Enter a valid phone number in the "Phone Number" field (e.g., "123-456-7890"). (Assume validation requires a specific format with hyphens)
    5.  Click the "Submit" button.
    6.  Observe the system's response.

*   **Expected Result:**

    1.  The system *does not* submit the form.
    2.  A clear and informative error message is displayed next to or below the "Email" field (e.g., "Please enter a valid email address." or "Invalid email format.").
    3. The error message must disappear or change when a correct email format is entered.
    4. The other fields (Name and Phone Number) retain the user's input. (This ensures good usability - the user doesn't have to re-enter all data).

*   **Priority:** High
