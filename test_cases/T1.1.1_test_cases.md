# Test Cases for T1.1.1 - Users Metrics

Okay, here are two detailed test cases based on the provided task: "Users Metrics: Track Total Registered Users, New Registrations, Active vs Inactive Users."

**Test Case 1: Total Registered Users Count Verification**

*   **Title:** Verify Total Registered User Count on the User Metrics Dashboard

*   **Description:** This test case verifies that the total registered user count displayed on the user metrics dashboard accurately reflects the total number of user accounts created in the system.

*   **Steps:**

    1.  **Preparation:** Ensure the system has a known number of registered users (e.g., 1000 users).  This can be achieved by creating or deleting test user accounts, or by referencing the backend database directly.
    2.  **Login:** Log in to the application with an account that has the appropriate permissions to access the User Metrics Dashboard (e.g., administrator).
    3.  **Navigate:** Navigate to the User Metrics Dashboard. The navigation path would be like "Admin Panel" > "Reporting" > "User Metrics"
    4.  **Locate:** Locate the "Total Registered Users" metric on the dashboard.
    5.  **Record:** Record the displayed total registered user count.
    6.  **Database Query (Backend Verification):** (Optional but highly recommended for accurate verification) Access the system's user database (e.g., via SQL) and execute a query to count the total number of user records (e.g., `SELECT COUNT(*) FROM users;`). Record the database result.
    7.  **Calculate Expected Result:** If you created new accounts or deleted existing ones, calculate the expected "Total Registered Users" based on initial users count + new accounts - deleted accounts.

*   **Expected Result:**

    *   The "Total Registered Users" count displayed on the User Metrics Dashboard must be **exactly equal** to the expected value calculated in Step 7.
    *   (If Step 6 is performed) The database query result from Step 6 must **exactly match** the displayed "Total Registered Users" count and the expected calculated value.
    *   If the system is expected to automatically update, verify that the time elapsed from the last registration until the dashboard is accessed is not greater than the expected auto-update delay.

*   **Priority:** High

**Test Case 2: New User Registrations Tracking and Display**

*   **Title:** Verify New User Registrations Count on the User Metrics Dashboard over a Specific Time Period

*   **Description:** This test case verifies the accuracy of the "New Registrations" metric displayed on the User Metrics Dashboard for a specific time period (e.g., daily, weekly, monthly). It ensures that new user accounts created within the specified time frame are correctly counted and displayed.

*   **Steps:**

    1.  **Preparation:** Determine the time period you want to test (e.g., the past 24 hours, the past week).
    2.  **Pre-Registration Count:** Note the number of new users registered on the dashboard.
    3.  **New Account Creation:** Create a specific number of new user accounts (e.g., 5 new accounts) using the standard user registration process within the chosen time period. Ensure these accounts are created successfully and that all required registration fields are populated correctly.
    4.  **Wait:** Wait for the user metrics dashboard to update (if applicable). Note the expected update frequency.
    5.  **Login:** Log in to the application with an account that has the appropriate permissions to access the User Metrics Dashboard (e.g., administrator).
    6.  **Navigate:** Navigate to the User Metrics Dashboard (e.g., "Admin Panel" > "Reporting" > "User Metrics").
    7.  **Locate:** Locate the "New Registrations" metric on the dashboard and select the time period being tested (e.g., "Last 24 Hours," "Last Week"). There might be a dropdown or filtering option to select the time range.
    8.  **Record:** Record the displayed "New Registrations" count.
    9.  **Database Query (Backend Verification):** (Optional, but highly recommended for increased confidence) Access the system's user database and execute a query to count the number of user records created within the specified time period. For example: `SELECT COUNT(*) FROM users WHERE registration_date >= DATE('now', '-1 day');` (for the last 24 hours). Adjust the date/time criteria based on the database system and the chosen time period.
    10. **Calculate Expected Result:** Expected new registrations count should be the pre-registration count + created accounts.

*   **Expected Result:**

    *   The "New Registrations" count displayed on the User Metrics Dashboard for the selected time period must be **exactly equal** to the expected value calculated in Step 10.
    *   (If Step 9 is performed) The database query result from Step 9 must **exactly match** the displayed "New Registrations" count and the calculated expected value.
    *   The time on the dashboard must reflect the last registration time.

*   **Priority:** High
