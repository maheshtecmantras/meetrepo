# Test Cases for T2.3 - Venue Performance Metrics

Okay, here are two detailed test cases based on the provided "Venue Performance Metrics" task, covering different aspects of the functionality:

**Test Case 1: Total Bookings Count Verification**

*   **Title:** Verify Total Bookings Count Accuracy on the Venue Performance Metrics Dashboard

*   **Description:** This test case verifies the accuracy of the Total Bookings count displayed on the Venue Performance Metrics Dashboard for a specific venue over a defined period. It ensures the system correctly aggregates booking data and reflects it on the dashboard.

*   **Steps:**

    1.  **Prerequisites:**
        *   Login to the system with a valid user account that has access to the Venue Performance Metrics Dashboard.
        *   Identify a specific venue for which to run the test. Note the venue ID.
        *   Define a date range for the test (e.g., last month, specific week).
        *   Manually count the number of confirmed bookings within the specified date range for the selected venue using raw booking data (e.g., database query, booking records). Document this manual count as the "Expected Bookings Count".
    2.  **Navigation:** Navigate to the Venue Performance Metrics Dashboard.
    3.  **Venue Selection:** Select the venue identified in the Prerequisites.
    4.  **Date Range Selection:** Select the date range identified in the Prerequisites.
    5.  **Data Observation:** Observe the "Total Bookings" value displayed on the dashboard for the selected venue and date range. Note down the value as "Displayed Bookings Count".
    6.  **Verification:** Compare the "Displayed Bookings Count" with the "Expected Bookings Count".

*   **Expected Result:**
    *   The "Displayed Bookings Count" on the Venue Performance Metrics Dashboard must exactly match the "Expected Bookings Count" calculated manually for the selected venue and date range. If there is a difference then the test case must fail.

*   **Priority:** High (Incorrect bookings count undermines the entire metric).

**Test Case 2:  Settlement Report Generation and Google Docs Integration**

*   **Title:** Verify Settlement Report Generation and Google Docs Integration for Venue Settlements

*   **Description:** This test case validates the functionality to generate a settlement report for a specific venue and successfully integrate with Google Docs to upload and share the report. It ensures the report generation process is accurate and that the Google Docs integration is working correctly.

*   **Steps:**

    1.  **Prerequisites:**
        *   Login to the system with a valid user account that has access to the Venue Performance Metrics Dashboard and settlement report generation functionality.
        *   Identify a specific venue for which to generate the settlement report.
        *   Define a settlement period (e.g., last month, specific week).
        *   Ensure the user account has necessary permissions to generate settlement reports and access the Google Docs integration.
        *   Ensure Google account is linked with the venue account.
        *   Have Google Docs open in a new tab.
    2.  **Navigation:** Navigate to the Venue Performance Metrics Dashboard.
    3.  **Venue Selection:** Select the venue identified in the Prerequisites.
    4.  **Settlement Report Generation:** Locate and click the "Generate Settlement Report" button/link.
    5.  **Date Range Selection:** Select the settlement period defined in the Prerequisites.
    6.  **Report Generation Confirmation:** Confirm the report generation request if prompted.
    7.  **Google Docs Integration:** Ensure the system successfully connects to the Google Drive. Check the generated file is named correctly, for example "Settlement Report Venue A - 2024-01-01 - 2024-01-31".
    8.  **Report Upload Verification:** Verify that a new document (e.g., Google Sheet) is created in the user's linked Google Docs account (or the designated folder). The title of the document should be descriptive of the venue and the settlement period.
    9.  **Report Content Verification:** Open the generated document in Google Docs. Validate that the document contains the expected settlement data, including:
        *   Booking IDs
        *   Booking Dates
        *   Booking Amounts
        *   Commission Rates
        *   Commission Amounts
        *   Total Settlement Amount
        *   Any applicable adjustments or deductions
    10. **Data Accuracy Verification:** Manually verify a sample of the data in the Google Docs report against the source booking data to ensure accuracy.
    11. **Sharing Verification:** Check if the file has the correct sharing permissions.

*   **Expected Result:**

    *   The system should successfully generate a settlement report for the selected venue and settlement period.
    *   The system should successfully integrate with Google Docs and upload the generated report as a new document (e.g., Google Sheet) to the user's linked Google Docs account.
    *   The title of the Google Docs document should be descriptive of the venue and settlement period.
    *   The document should contain all the expected settlement data, including booking details, commission calculations, and total settlement amount.
    *   The data within the Google Docs report should be accurate when compared to the source booking data.
    *   The document should have the correct permissions.

*   **Priority:** High (Failure to generate and integrate settlement reports impacts financial accuracy and venue relationships).
