**Test Case 1: Setting User Status to Active Member**

*   **Title:** Verify User Status Update to "Active Member"

*   **Description:** This test case verifies that a user's status can be successfully updated to "Active Member" and that the change is reflected correctly in the system. It focuses on ensuring that the UI and underlying data are synchronized after the update.

*   **Steps:**

    1.  **Precondition:** Log in to the application with an account that has the necessary permissions to modify user statuses (e.g., an administrator account).
    2.  **Precondition:** A user account exists in the system with a status other than "Active Member" (e.g., "Invited" or "Suspended").  Note/capture the initial status of the user before proceeding.
    3.  **Navigate:** Navigate to the user management section of the application.
    4.  **Locate User:** Find the user account created in step 2 using the search or filter functionality.
    5.  **Initiate Status Change:** Select the user account and initiate the status change process (e.g., click on "Edit," "Change Status," or a similar action).
    6.  **Select Status:** From the available status options, select "Active Member".
    7.  **Confirm Action:** Confirm the status change (e.g., by clicking "Save," "Update," or a similar button).
    8.  **Observe UI:** Observe the user details panel in the UI to confirm that the status is now displayed as "Active Member".

*   **Expected Result:**

    1.  The user's status is successfully updated to "Active Member" in the system.
    2.  The user details panel in the UI reflects the updated status of "Active Member".
    3.  A success message or confirmation notification is displayed to indicate successful status update. (If Applicable)
    4.  Auditing logs record the change with the correct user, timestamp and action if enabled
    5.  Any other system integrations that rely on user status correctly reflect the change. (e.g. messaging access)

*   **Priority:** High (This is a core function of user management.)

**Test Case 2: Setting User Status to Suspended/Inactive and Verify Impact**

*   **Title:** Verify User Status Update to "Suspended/Inactive" and Impact on User Access

*   **Description:** This test case verifies that a user's status can be successfully updated to "Suspended/Inactive" and that the update correctly restricts the user's access to the system. It tests both the update process and the enforcement of access restrictions.

*   **Steps:**

    1.  **Precondition:** Log in to the application with an account that has the necessary permissions to modify user statuses (e.g., an administrator account).
    2.  **Precondition:** A user account exists in the system with "Active Member" status.  Note the user ID or username.
    3.  **Navigate:** Navigate to the user management section of the application.
    4.  **Locate User:** Find the user account created in step 2 using the search or filter functionality.
    5.  **Initiate Status Change:** Select the user account and initiate the status change process (e.g., click on "Edit," "Change Status," or a similar action).
    6.  **Select Status:** From the available status options, select "Suspended/Inactive".
    7.  **Confirm Action:** Confirm the status change (e.g., by clicking "Save," "Update," or a similar button).
    8.  **Observe UI:** Observe the user details panel in the UI to confirm that the status is now displayed as "Suspended/Inactive".
    9.  **Attempt Login:** Using the credentials of the user whose status was changed, attempt to log into the application.

*   **Expected Result:**

    1.  The user's status is successfully updated to "Suspended/Inactive" in the system.
    2.  The user details panel in the UI reflects the updated status of "Suspended/Inactive".
    3.  The user is unable to log into the application.
    4.  A relevant error message is displayed upon attempting to log in, indicating that the account is suspended or inactive. (e.g., "Account Disabled", "Login Failed", "User Inactive")
    5.  Auditing logs record the change with the correct user, timestamp and action.
    6.  Any scheduled tasks or processes associated with the user are suspended or terminated (if applicable based on the system's design).

*   **Priority:** High (This is critical for security and proper access control.)
