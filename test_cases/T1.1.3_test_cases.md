# Test Cases for T1.1.3 - Events Metrics

Okay, I can do that. Here are two detailed test cases based on the "Events Metrics" task, focusing on tracking the count of upcoming events and identifying the most popular events.

**Test Case 1: Upcoming Events Count Accuracy**

*   **Title:** Verify Accurate Count of Upcoming Events on Events Dashboard

*   **Description:** This test case validates that the system accurately displays the total number of upcoming events in the events dashboard. This ensures users have an accurate overview of scheduled events.

*   **Steps:**

    1.  **Pre-condition:** Ensure the test environment contains a known number of events in "Scheduled" status with future start dates. Let's assume there are 10 events scheduled for the next 7 days and 5 events scheduled for the next month.
    2.  Log in to the application as a user with access to the events dashboard.
    3.  Navigate to the events dashboard page.
    4.  Locate the "Upcoming Events" count metric display.
    5.  Verify the displayed "Upcoming Events" count.
    6.  Log in to the application as an admin.
    7.  Navigate to the admin panel where event management occurs.
    8.  Verify the "Scheduled" events with future start dates in the next 7 days and next month match the count displayed on the events dashboard.
    9.  Create 2 new events with a start date within the next 7 days and set the status to "Scheduled".
    10. Return to the events dashboard.
    11. Verify the "Upcoming Events" count has increased by 2.
    12. Change the status of the 2 newly created events to "Cancelled" through the admin panel.
    13. Return to the events dashboard.
    14. Verify the "Upcoming Events" count has decreased by 2.

*   **Expected Result:**

    *   Step 5: The "Upcoming Events" count on the dashboard should exactly match the number of events in "Scheduled" status with future start dates in the system.
    *   Step 8: The number of events scheduled on the admin panel should match the count displayed on the events dashboard.
    *   Step 11: The "Upcoming Events" count on the dashboard should be incremented by 2.
    *   Step 14: The "Upcoming Events" count on the dashboard should be decremented by 2.

*   **Priority:** High - Accurate event counts are crucial for user awareness and planning. Inaccurate counts could lead to missed events or confusion.

**Test Case 2: Most Popular Events Calculation**

*   **Title:** Verify Accuracy of "Most Popular Events" Metric Based on Attendance/Registration.

*   **Description:** This test case validates the system's ability to correctly identify and display the most popular events based on a predefined metric, such as registration count or attendance rate. This metric should be configurable.

*   **Steps:**

    1.  **Pre-condition:** Ensure the test environment contains at least 5 events with varying numbers of registrations/attendees.  The "Most Popular Events" metric is configured to use "Registration Count". Event A should have 100 registrations, Event B 75, Event C 50, Event D 25, and Event E 10.
    2.  Log in to the application as a user with access to the events dashboard.
    3.  Navigate to the events dashboard page.
    4.  Locate the "Most Popular Events" section (if this is configurable, it should be enabled).
    5.  Verify that the "Most Popular Events" section is displaying events ranked according to their registration counts.
    6.  Verify the order of events in the "Most Popular Events" section matches the expected order based on registration counts (e.g., Event A should be first, then Event B, then Event C). Display order should be from most to least popular.
    7.  Register 20 new users for Event C.
    8.  Navigate to the events dashboard page.
    9.  Verify that the "Most Popular Events" section is updated to reflect Event C's new registration count. If Event C's new count now surpasses Event B, the display order should reflect this.
    10. Navigate to the Admin Panel
    11. Update the metric used for "Most Popular Events" to "Attendance Rate"
    12. Record the current attendance rate for each event
    13. Navigate to the events dashboard page
    14. Verify the "Most Popular Events" section is updated to reflect the new metric, "Attendance Rate" and the ranking of events has changed.

*   **Expected Result:**

    *   Step 5: The "Most Popular Events" section should display events based on the configured metric (Registration Count initially).
    *   Step 6: The events should be ranked correctly, with the event having the highest registration count displayed first, followed by the event with the second-highest, and so on. In our example, the order should be A, B, C, D, E.
    *   Step 9: The "Most Popular Events" section should update to show Event C's updated ranking. If Event C now has more registrations than Event B (70 > 75 is false, 70 > Event A would be very surprising), the order should change. In this case, Event C should remain in the same position, assuming no events were added or their registration count changed, or if event A has significantly more registrants than Event C.
    *   Step 14: The "Most Popular Events" section should display events based on the Attendance Rate metric and be displayed in order of highest attendance rate to lowest.

*   **Priority:** Medium - While not as critical as accurate counts, properly identifying popular events is important for marketing, resource allocation, and understanding user preferences.  A misidentification could lead to inefficient resource usage or missed opportunities.
