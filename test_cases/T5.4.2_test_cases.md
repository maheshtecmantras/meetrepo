**Test Case 1: Manual User Activation and Membership Confirmation**

*   **Title:** Verify Manual User Activation and Subsequent Membership Confirmation

*   **Description:** This test case verifies the process of manually approving a newly registered user through the admin interface, focusing on ensuring the user account is activated and that membership confirmation emails are correctly sent. This will test the functionality where an administrator must manually approve a new user's account, ensuring all the necessary steps and notifications are completed.

*   **Steps:**

    1.  **Pre-condition:** User registration flow configured for manual approval.
    2.  **Step 1:** Register a new user account through the standard registration process (e.g., website form) using a valid, unique email address and required user information.
    3.  **Step 2:** Log in to the administrative interface using an account with appropriate user management permissions.
    4.  **Step 3:** Navigate to the "User Management" or "Pending User Approvals" section.
    5.  **Step 4:** Locate the newly registered user account in the pending approvals list.
    6.  **Step 5:** Select the user account and initiate the "Approve" or "Activate" action.
    7.  **Step 6:** Confirm the activation action (if prompted).
    8.  **Step 7:** Log out of the administrative interface.
    9.  **Step 8:** Access the email inbox associated with the registered user.
    10. **Step 9:** Verify the user receives a "Membership Confirmation" email.
    11. **Step 10:** Attempt to log in to the platform using the newly activated user's credentials.

*   **Expected Result:**

    1.  The new user account is successfully created with a status of "pending approval."
    2.  The user account is successfully marked as "active" or "approved" in the administrative interface.
    3.  The "Membership Confirmation" email is received by the user within a reasonable timeframe (e.g., 5 minutes). The email should contain:
        *   A clear subject line indicating successful account activation.
        *   A personalized greeting.
        *   Information about the platform and next steps (e.g., login instructions).
    4.  The user is able to successfully log in to the platform using the credentials provided during registration.

*   **Priority:** High

**Test Case 2: Automatic User Activation Failure due to Invalid Email Address and Error Handling**

*   **Title:** Verify Automatic User Activation Fails with Invalid Email and Proper Error Message

*   **Description:** This test case verifies the system's behavior when a user attempts to register with an invalid email address when the system is set to automatically approve users. It aims to validate that the system correctly identifies the invalid email, prevents activation, and displays an appropriate error message to the user. This test aims to cover negative testing on edge cases.

*   **Steps:**

    1.  **Pre-condition:** User registration flow configured for automatic approval.
    2.  **Pre-condition:** System configured to validate email address format.
    3.  **Step 1:** Attempt to register a new user account through the standard registration process using an *invalid* email address (e.g., "test@test", "test@.com", "test@test..com") and other required user information.
    4.  **Step 2:** Check for an immediate error message displayed on the registration form/page.
    5.  **Step 3:** Check for an activation email.

*   **Expected Result:**

    1.  The system **should not** create a user account with the invalid email address.
    2.  An immediate, user-friendly error message is displayed on the registration form, clearly indicating that the email address format is invalid (e.g., "Please enter a valid email address.").
    3.  No activation email is sent to the invalid email address.
    4.  The user is not able to log in with the credentials they provided.

*   **Priority:** High
