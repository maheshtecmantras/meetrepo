# Test Cases for T9.1 - Track KPIs

Okay, here are two detailed test cases for tracking KPIs, covering two different aspects of the specified task. I've tried to focus on accuracy and thoroughness while providing a clear structure.

**Test Case 1**

*   **Title:** Verify Weekly Active User (WAU) Metric Calculation and Display

*   **Description:** This test case validates the accuracy of the Weekly Active User (WAU) calculation and its correct display in the KPI dashboard. It verifies that only truly active users within the specified weekly period are counted, based on predefined activity criteria.

*   **Steps:**

    1.  **Pre-Condition:** Ensure the user role has access to the KPI Dashboard
    2.  **Data Setup:**
        *   **Week 1 (Current Week):** Create 10 new user accounts.  Have 5 of these accounts log in and perform at least one action (e.g., browse a venue, RSVP to an event, make a purchase) within the current week.  The other 5 accounts should not perform any actions.
        *   **Week 2 (Last Week):**  Create 8 new user accounts. Have 4 of these accounts log in and perform at least one action within the previous week but NOT the current week. The other 4 accounts should not perform any actions. Ensure no actions from last week should be counted for the current week.
    3.  **Navigation:** Log in to the application as a user with access to the KPI Dashboard.
    4.  **Action:** Navigate to the KPI Dashboard.
    5.  **Verification:** Locate the "Weekly Active Users" metric.
    6.  **Verification:** Locate the date filter/picker for KPI data and ensure date range is correctly set to the current week (Monday-Sunday). If the app supports it, also check that the date range is configurable and can be set to the correct week using the date filter.
    7.  **Action:** If possible, drill down into the WAU data to view the list of users counted as active for the current week.

*   **Expected Result:**

    1.  The "Weekly Active Users" metric on the KPI Dashboard should display a value of **5**.
    2.  Drilling down into the WAU data should show a list of only the 5 users who performed actions within the specified week (current week, from pre-condition). The list should NOT include the 4 users from last week.
    3.  The date filter should correctly set the week's start and end dates. If the date filter is configurable, setting an invalid date range should return an error or no results.

*   **Priority:** High (P1) -  WAU is a fundamental metric for understanding user engagement and business health. Inaccurate data here will skew all further analysis.

**Test Case 2**

*   **Title:** Validate Member Conversion Rate Calculation and Display

*   **Description:** This test case validates the accurate calculation and display of the Member Conversion Rate KPI on the KPI dashboard. It focuses on ensuring the correct number of trial/free users are converted to paid members within the specified time period (monthly).

*   **Steps:**

    1.  **Pre-Condition:** Ensure the user role has access to the KPI Dashboard
    2.  **Data Setup:**
        *   **Month 1 (Current Month):** Create 20 new free/trial user accounts.  Manually convert 5 of these accounts to paid memberships during the current month.
        *   **Month 2 (Previous Month):** Create 15 new free/trial user accounts. Manually convert 3 of these accounts to paid memberships during the previous month. Ensure those conversions are properly timestamped and not counted for the current month.
    3.  **Database Verification:** Directly query the database to confirm the correct number of free/trial users created and converted for both months. This is a crucial pre-step to guarantee the data integrity being used for the test.
    4.  **Navigation:** Log in to the application as a user with access to the KPI Dashboard.
    5.  **Action:** Navigate to the KPI Dashboard.
    6.  **Verification:** Locate the "Member Conversion Rate" metric.
    7.  **Verification:** Locate the date filter/picker for KPI data and ensure the date range is correctly set to the current month. If the app supports it, also check that the date range is configurable and can be set to the correct month using the date filter.
    8.  **Action:** If possible, drill down into the Member Conversion Rate data to view the details of the calculation (e.g., total free/trial users, number of conversions).

*   **Expected Result:**

    1.  The "Member Conversion Rate" metric on the KPI Dashboard should display a value of **25%** (5 conversions / 20 free/trial users * 100).
    2.  If drill-down is available, it should display:
        *   Total Free/Trial Users (Current Month): 20
        *   Total Conversions to Paid Members (Current Month): 5
    3.  The date filter should correctly set the month's start and end dates. If the date filter is configurable, setting an invalid date range should return an error or no results. Data from the previous month (Month 2) should *not* be included in the calculation.
    4.  The conversion percentage should be correctly formatted (e.g., with a percentage sign, appropriate number of decimal places).

*   **Priority:** High (P1) - Conversion Rate is a critical metric for evaluating business growth and marketing effectiveness. Inaccurate reporting can lead to misguided strategic decisions.
