# Test Cases for T5.3 - User History

Okay, here are two detailed test cases covering aspects of the User History feature, as you requested. These test cases focus on different areas of the functionality to provide broader coverage.

**Test Case 1: Events Attended Tracking**

*   **Title:** Verify Correct Tracking of Events Attended in User History

*   **Description:** This test case verifies that the system correctly tracks and displays the events a user has attended in their user history. This includes accurate recording of event names and dates.

*   **Steps:**

    1.  **Login:** Log in to the application as a test user with an existing account.
    2.  **Navigate to Events:** Navigate to the "Events" section of the application.
    3.  **Register for an Event:** Register the test user for a specific event (e.g., "Tech Conference 2024"). Ensure the registration is successful and confirmed.
    4.  **Attend Event:** Simulate the user attending the event (e.g., if there's a check-in process, complete it).
    5.  **Navigate to User History:** Navigate to the user's profile and then to the "User History" section.
    6.  **Verify Events Attended:** Locate the "Events Attended" section within the User History.
    7.  **Repeat with Multiple Events:** Repeat steps 3-6 with a different event or events to ensure multiple events are tracked correctly. Vary the event types (e.g., webinar, in-person workshop).
    8. **Verify Event Display Order:** Check the order in which events are displayed (chronological, reverse chronological, etc.) against documented specifications.
*   **Expected Result:**

    *   The "Events Attended" section in the User History should display a list of events the user has attended.
    *   For each event, the following information should be displayed accurately:
        *   Event Name (e.g., "Tech Conference 2024")
        *   Event Date (e.g., "October 26, 2024")
        *   The events should be displayed in the expected order (as specified).
        *   There should be no duplicate entries for the same event.
    *   If the user hasn't attended any events, the "Events Attended" section should display a message indicating that no events have been attended yet (e.g., "No events attended").

*   **Priority:** High (Critical for core functionality)

**Test Case 2: Referrals Made Tracking and Display**

*   **Title:** Verify Correct Tracking and Display of Referrals Made in User History.

*   **Description:** This test case verifies that the system accurately tracks and displays the referrals made by a user and the status of those referrals in their user history.

*   **Steps:**

    1.  **Login:** Log in to the application as a test user with an existing account who has referral capabilities.
    2.  **Navigate to Referral Section:** Navigate to the section of the application that allows the user to make referrals.
    3.  **Create Referrals:** Create several referrals using different email addresses (e.g., referral1@example.com, referral2@example.com, referral3@example.com).
    4.  **Simulate Referral Outcomes:**
        *   For one referral (referral1@example.com), simulate the referred user successfully signing up and becoming an active user.
        *   For another referral (referral2@example.com), simulate the referred user signing up but not becoming an active user (e.g., not completing profile setup).
        *   For the third referral (referral3@example.com), do not simulate any action by the referred user.
    5.  **Navigate to User History:** Navigate to the user's profile and then to the "User History" section.
    6.  **Verify Referrals Made Section:** Locate the "Referrals Made" section within the User History.
    7.  **Verify Referral Information:** For each referral, verify the following:
        *   The correct email address of the referred user is displayed.
        *   The date the referral was made is displayed.
        *   The status of the referral is displayed accurately (e.g., "Pending," "Signed Up," "Active User").
        *   Any applicable referral bonuses or rewards associated with the referral are displayed.
*   **Expected Result:**

    *   The "Referrals Made" section in the User History should display a list of all referrals made by the user.
    *   For each referral, the following information should be accurate:
        *   Referred User's Email Address (e.g., "referral1@example.com")
        *   Date of Referral
        *   Referral Status:
            *   "referral1@example.com" should have a status of "Active User" (or equivalent).
            *   "referral2@example.com" should have a status of "Signed Up" (or equivalent).
            *   "referral3@example.com" should have a status of "Pending" (or equivalent).
        *   The number of Referrals made should be accurate in the User History
    *   If the user has not made any referrals, the "Referrals Made" section should display a message indicating that no referrals have been made yet (e.g., "No referrals made").

*   **Priority:** High (Important for user engagement and growth initiatives)
